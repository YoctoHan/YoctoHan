# Field Notebook — design notes for the profile README

## Concept
The profile is a working scientist's notebook. Every SVG asset is a sheet from the same book:
a paper panel with 10 px corners, a dot grid in light mode / a blueprint grid in dark mode,
numbered figures and tables ("Fig. n —", "Table 1 —"), and italic margin notes in a second ink.
Light mode is cream engineering paper with brown ink, blue figure lines and rust annotations;
dark mode is the same drawing re-inked as a navy blueprint with pale-cyan lines and amber
annotations — two inks on two papers, not an inverted palette.

Everything load-bearing is native Markdown/HTML: the bio (§ 1), every repo/fork link (§ 4),
the contact line (§ 5) and all headings. SVG is used only where it can afford to be decorative
at phone width: the hero sheet, the figure plate, Table 1 and the hobby strip. There are no
`<table>`s, no badges, no third-party widgets, no dates and no invented numbers.

## Page order
1. Hero sheet (SVG) — wordmark, tagline, margin note, equation (1), Fig. 0 roofline, title block
   CONTACT · LOCATION · TRAINING · FOCUS · GITHUB.
2. `### § 1 — Notes` — two native paragraphs.
3. `### § 2 — Figures` — one plate SVG holding Fig. 1 (causal attention) and Fig. 2 (CUDA hierarchy).
4. `### § 3 — Instruments` — Table 1 SVG (ruled rows, outlined chips, "← now" flag on Inference).
5. `### § 4 — Selected work` — five native entries (`**01** name `lang`<br>description`) + shelf line.
6. `### § 5 — Contact` — native sentence with the mailto and profile links.
7. `### Appendix A — Off the keyboard` — icon strip SVG (no title inside the image).

Panels sit directly on GitHub's page colour. Body text uses GitHub's own colours.

## Type
- Sans (GitHub system stack) for names, taglines, captions, chips, margin notes (italic = note).
- Mono (GitHub mono stack) for overlines, axis labels, CUDA identifiers, table row labels.
- Serif (Georgia / Times, system fallbacks) only for equation (1); operator names upright,
  variables italic; the superscript T is a `<tspan>`.
- No web fonts, no `foreignObject`, no scripts, no external requests. One SMIL radius pulse on the
  "after" point of Fig. 0, with a static fallback.
- Floor: no text below 10.5 units in an 880-wide viewBox (~10 px in GitHub's 832 px column).
  Captions 11.5, sub-captions 11, chips 11.5, title-block values 12, hobby labels 12.

## Editing copy and regenerating
- Native copy (bio, repo list, contact): edit `README.md` directly. Keep blank lines around every
  HTML block and keep the `**nn** &nbsp;[**name**](url) \`lang\`<br>description` shape in § 4 (the
  code chip is the separator). In the shelf line, `flash&#8209;attention` uses a non-breaking
  hyphen so the name cannot split across two lines on a phone; the `href` keeps the ASCII hyphen.
- Anything inside an image (tagline, title block, chips, captions, hobby labels): edit the strings
  in `tools/build_assets.py`, then run

  ```bash
  python3 tools/build_assets.py
  ```

  (standard library only). It rewrites all eight SVGs in `assets/` from one geometry and two
  palettes (`PAL`).
- The generator refuses to ship a label that could clip: every `text()` call declares the lane it
  must fit, `budget()` estimates the run pessimistically (0.58 em/char sans, 0.62 mono, 0.55 serif,
  plus letter-spacing) and demands 12 % slack; `MIN_FONT = 10.5` rejects anything smaller. If a
  build stops with `OVERFLOW …`, shorten the string or widen its lane — do not lower the guard.
  (This is why the Fig. 1 caption says "8 tokens": "eight tokens" needs 411 units of a 384 lane.)
- Every layout guard raises `SystemExit` through `check()` (never a bare `assert`, which `python3 -O`
  would strip), attribute values go through `attr()` so a `"` cannot break the XML, and each file is
  parsed with `xml.etree` before it is written. `selftest()` covers the guards themselves.
- Superscripts are `<tspan dy>` runs; a tspan's baseline shift persists after it closes, so
  `sup_T(..., tail=...)` always emits a second tspan that shifts back. Use it for anything that
  follows a superscript.
- Chip widths in Table 1 and the hobby-strip spacing are computed from the same estimates, so new
  chips or longer labels lay themselves out.
- To preview like GitHub before pushing:

  ```bash
  python3 tools/preview.py --mobile
  ```

  It runs `README.md` through GitHub's own markdown renderer (needs the `gh` CLI, logged in),
  points the image URLs at the local `assets/`, wraps the result in `github-markdown-css`, and
  screenshots both colour schemes with headless Google Chrome into `.preview/` (git-ignored):
  `light.png`, `dark.png`, 1100 px tiles, and with `--mobile` a 390 px phone view. `--no-shot`
  writes only the HTML. Both schemes are resolved explicitly in the HTML because headless Chrome
  can report the dark scheme regardless of the OS.
- Replacing an asset later: bump the file name (GitHub's image proxy caches SVGs aggressively) and
  update both `README.md` references.

## Repository layout
- `README.md` — the profile page
- `assets/` — the eight generated SVGs
- `tools/build_assets.py`, `tools/preview.py`, `tools/README.md` — generator, local previewer, these notes

Nothing else is required: no Actions, no third-party services, no tokens.
